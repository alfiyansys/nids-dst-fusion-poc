# Fusible sample data

Real Snort JSON-alert and Suricata EVE-JSON output, in their genuine on-wire
schema, with synthetic (not captured-traffic) content: 10 temporally-aligned
alert pairs plus one Suricata SSH protocol-detection record, spanning
`2026-03-27T10:00:00` to `2026-03-27T10:00:10.888`.

## Provenance

Generated by `generate-synthetic-data.sh`, part of the `test-data/fusible/`
fixture set in the Hyper-Parser repository (the production codebase this
paper's Fusion Engine ships in):

```
hyper_sensor/hyper-parser/test-data/fusible/
```

That script and its sibling tools (`generate-fusible-data.sh`,
`validate-fusible-data.sh`) are documented in that repository's own
`test-data/fusible/README.md`; these three JSON files are the same script's
output copied here so this notebook repo is self-contained and does not
depend on that repository being checked out locally.

## Why this data, not the paper's PCAP

The paper's Table 2 results come from a separate, larger PCAP replay
(`nids_test.pcap`, 6,000 flows) run directly against a live Snort +
Suricata + tap0 pipeline; that raw capture was never kept as a versioned
artifact, only its aggregate output counts. This fixture set is what *is*
still available: small, real engine-output JSON designed specifically to
exercise cross-engine fusion (see `metadata_synthetic_20260327_014143.json`
for the four fusion scenarios it encodes: exact-duplicate SSH scan,
exact-duplicate SQL port scan, complementary SSH evidence, and
exact-duplicate DOS detection).

`notebooks/dst_fusion_analysis.ipynb` uses it to demonstrate the ported
correlator against genuine engine output, then separately builds a
calibrated 6,000-flow synthetic dataset (`dst_fusion.simulate`) to reproduce
Table 2 itself — see that notebook section for why the two are kept
distinct rather than conflated.
